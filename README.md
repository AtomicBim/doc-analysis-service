# 📋 Сервис анализа проектной документации

Интеллектуальная система для автоматического анализа строительной проектной документации с использованием OpenRouter API и моделей Gemini.

## 🎯 Возможности

- **Двухэтапный процесс**: Сначала извлечение требований из ТЗ, затем анализ проектной документации по этим требованиям.
- **Умное извлечение требований**: Автоматическая сегментация и классификация требований из PDF или DOCX файлов с техническим заданием.
- **Редактор требований**: Интерактивный интерфейс для проверки, редактирования и выбора требований перед анализом.
- **Визуальный анализ чертежей**: Анализ PDF-документов (включая сканы) через OpenRouter API с использованием моделей Google Gemini.
- **3-стадийный анализ**:
  - **Stage 1**: Извлечение метаданных страниц (штампы, заголовки, номера листов).
  - **Stage 2**: Оценка релевантности страниц для каждого требования с использованием текстового префильтра и визуального анализа.
  - **Stage 3**: Детальный анализ релевантных страниц в высоком разрешении для проверки соответствия требованиям.
- **Интерактивный UI**: React-приложение с возможностью навигации по PDF, подсветкой текста и сохранением прогресса.
- **Умная навигация**: Автоматическое распознавание номеров листов и создание "горячих" ссылок для быстрого перехода к нужным чертежам.
- **Сохранение состояния**: Прогресс и результаты анализа автоматически сохраняются в `localStorage`, позволяя продолжить работу после перезагрузки страницы.

## 🏗️ Архитектура

Система состоит из двух основных сервисов, работающих в Docker-контейнерах.

```
┌─────────────────────────────────────────┐
│   Frontend (React + TypeScript)         │
│   - Загрузка файлов (ТЗ и Проект)       │
│   - Редактирование и выбор требований   │
│   - Просмотр результатов и PDF с        │
│     подсветкой и навигацией             │
│   - Nginx (Port: 7862)                  │
└────────────────┬────────────────────────┘
                 │ HTTP API
┌────────────────▼────────────────────────┐
│   Backend (FastAPI + Python)            │
│   - Интеграция с OpenRouter API (Gemini)│
│   - Обработка PDF (PyMuPDF, OCR)        │
│   - Многостадийный конвейер анализа     │
│   - Трекинг прогресса                   │
│   - Uvicorn (Port: 8002)                │
└─────────────────────────────────────────┘
```

## 🚀 Быстрый старт

### Предварительные требования

- Docker и Docker Compose
- OpenRouter API ключ ([получить здесь](https://openrouter.ai/keys))

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd doc-analysis-service
```

### 2. Настройка API ключа

Создайте файл `api-service/.env` на основе примера:

```bash
cd api-service
cp .env.example .env
```

Откройте `api-service/.env` в текстовом редакторе и вставьте ваш OpenRouter API ключ:

```env
OPENROUTER_API_KEY="sk-or-v1-..."
```

### 3. Запуск сервиса

Вернитесь в корневую директорию проекта и выполните команду:

```bash
docker-compose up --build
```

Первый запуск может занять 3-5 минут для сборки Docker-образов.

### 4. Открытие приложения

Откройте браузер и перейдите по адресу:

```
http://localhost:7862
```

## 📖 Использование

### Шаг 1: Извлечение требований из ТЗ

1.  В блоке "Шаг 1" нажмите "Выбрать файл" и загрузите PDF или DOCX файл с техническим заданием.
2.  Нажмите кнопку **"📋 Извлечь требования из ТЗ"**.
3.  Дождитесь окончания обработки (1-3 минуты). Появится модальное окно с извлеченными требованиями.
4.  **Проверьте и отредактируйте** текст требований, если необходимо.
5.  Снимите галочки с нерелевантных требований, которые не нужно анализировать.
6.  Нажмите **"✓ Подтвердить и продолжить"**.

### Шаг 2: Анализ проектной документации

1.  После подтверждения требований интерфейс переключится на "Шаг 2".
2.  Выберите стадию проекта (ФЭ, ЭП).
3.  Загрузите PDF файл с проектной документацией.
4.  Нажмите **"🔍 Выполнить анализ проекта"**.
5.  Процесс анализа занимает от 5 до 30 минут. Прогресс будет отображаться в верхней панели.
6.  После завершения результаты появятся в левой панели. Нажимайте на требования или ссылки в них для навигации по PDF.

## ⚙️ Конфигурация

### Backend (`api-service/config.py`)

Ключевые параметры для настройки производительности и качества анализа:

- `STAGE1_MAX_PAGES`: Макс. страниц для анализа метаданных.
- `STAGE2_MAX_PAGES_PER_REQUEST`: Количество страниц, отправляемых в одном запросе на этапе оценки релевантности.
- `STAGE3_BATCH_SIZE`: Количество требований, анализируемых в одном пакете на этапе детального анализа.
- `OPENROUTER_MODEL`: Используемая модель, например `google/gemini-pro-1.5` или `google/gemini-flash-1.5`.

### Frontend (`ui-react-service/package.json`)

- `proxy`: URL backend-сервиса для локальной разработки без Docker.

## 🐛 Решение проблем

### Проблема: Ошибка "OPENROUTER_API_KEY не установлен"
**Решение**: Убедитесь, что файл `api-service/.env` существует, назван правильно (без `.example`) и содержит корректный API ключ.

### Проблема: "Rate limit exceeded" (Превышен лимит запросов)
**Решение**: OpenRouter API имеет лимиты. Уменьшите "агрессивность" запросов в файле `api-service/config.py`:
- Уменьшите `STAGE3_BATCH_SIZE` (например, до `5`).
- Уменьшите `STAGE2_MAX_PAGES_PER_REQUEST` (например, до `20`).

### Проблема: PDF-вьювер не загружается или работает некорректно
**Решение**: Очистите кэш браузера и перезагрузите страницу (Ctrl+Shift+R или Cmd+Shift+R). Данные анализа восстановятся из `localStorage`.

## 🔒 Безопасность

- **API ключи**: Храните `.env` файлы в безопасности. Они уже добавлены в `.gitignore` и **никогда** не должны попадать в Git.
- **Read-only Volume**: `.env` файл монтируется в Docker-контейнер в режиме "только для чтения" для дополнительной безопасности.
- **Изоляция сети**: Сервисы изолированы в виртуальной сети Docker.
